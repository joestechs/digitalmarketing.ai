Technical SEO

Technical SEO ensures search engines can efficiently crawl, render, and index your site — and that your pages load fast enough for both users and ranking algorithms to reward them.

robots.txt

A plain-text file at your domain root that tells crawlers which paths they may or may not request.

/robots.txt
User-agent: *
Disallow: /admin/
Disallow: /cart/
Disallow: /*?sessionid=
Allow: /

Sitemap: https://example.com/sitemap.xml
⚠ Common Mistake

Accidentally leaving Disallow: / in production after launching from staging. This blocks the entire site from being crawled — always double check robots.txt after a deploy.

XML sitemap

/sitemap.xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://example.com/</loc>
    <lastmod>2026-08-01</lastmod>
    <changefreq>weekly</changefreq>
    <priority>1.0</priority>
  </url>
  <url>
    <loc>https://example.com/blog/seo-guide/</loc>
    <lastmod>2026-07-20</lastmod>
  </url>
</urlset>

Submit the sitemap URL directly in Google Search Console to speed up discovery of new/updated pages.

Canonical tags

Prevent duplicate-content issues when the same content is reachable at multiple URLs (e.g. with and without tracking parameters):

index.html
<link rel="canonical" href="https://example.com/product/blue-shirt/" />

Core Web Vitals

MetricMeasuresGood threshold
LCP (Largest Contentful Paint)Loading speed of the main content≤ 2.5s
INP (Interaction to Next Paint)Responsiveness to user input≤ 200ms
CLS (Cumulative Layout Shift)Visual stability while loading≤ 0.1

Test with PageSpeed Insights, Lighthouse (built into Chrome DevTools), or field data from Google Search Console → Core Web Vitals report.

Mobile-first & HTTPS

Google indexes the mobile version of your site by default ("mobile-first indexing"). Ensure responsive layouts, tappable button sizes (≥44px), and readable font sizes without zooming. HTTPS is a baseline ranking signal and a hard requirement for modern browser features.

Rendering: SSR vs. CSR

Search engines can render JavaScript, but it's slower and less reliable than parsing plain HTML. If your site is a heavy client-side rendered (CSR) app (e.g. a pure client-side React SPA), consider Server-Side Rendering (SSR) or Static Site Generation (SSG) for SEO-critical pages so crawlers see full content immediately, without waiting on a JS render pass.

Quick technical SEO audit checklist

  • Site returns correct HTTP status codes (no soft 404s serving 200)
  • robots.txt doesn't block important paths
  • XML sitemap is valid, submitted, and free of non-canonical URLs
  • Every page has a self-referencing canonical tag (or points correctly to the preferred version)
  • Core Web Vitals pass on real mobile devices, not just desktop
  • No broken internal links (404s) or redirect chains longer than 1 hop
🎯 Interview Corner

Q: A page isn't appearing in Google despite being live for weeks. How do you debug it?
A: Check Google Search Console's URL Inspection tool first — it tells you exactly why (not indexed, crawled but not indexed, blocked by robots.txt, noindex tag present, duplicate/canonicalized elsewhere). Then verify internal links point to it, it's in the sitemap, and it isn't accidentally set to noindex.
